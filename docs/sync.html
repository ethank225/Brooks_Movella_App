Deep Dive: Sync & Record Flow

Two-step sync-then-record process, per-UUID suppression, and device reference freezing.

Step-by-Step Lifecycle

This is the complete chain from “sensors are .ready” through sync and recording. Sync is required before recording when 2+ sensors are assigned to a runner — beginSession guards on device.isSynced() and refuses to proceed otherwise.

Sync (~15 seconds)

User taps “Sync Sensors” →

1. Lock down sync state (stateQueue)

resyncRunner(runnerId)
  ├─ guard: phase == .idle, no other runner syncing, 2+ ready dots
  ├─ resyncingRunnersInternal.insert(runnerId)
  ├─ registry.syncingUuids = {uuid1, uuid2}     // freeze device refs
  ├─ registry.syncInProgress = true              // block connections
  └─ notify()                                     // UI shows spinner

At this point: connections are blocked, disconnect events for these UUIDs are suppressed, device references are frozen so the SDK can work with stable pointers.

2. SDK sync (sdkQueue, ~15 seconds)

performSync(dots:runnerId:completion:)
  ├─ snapshot device references (before SDK can mutate them)
  └─ DotSyncManager.startSync(devices) { results in ... }

During this time the SDK internally disconnects and reconnects each sensor. Those events are suppressed via syncingUuids — the user sees nothing.

3. Parse results and cleanup (stateQueue)

completion fires with SyncResult:
  ├─ parse per-sensor success/failure
  ├─ dot.refreshSyncStatus() on each    // device.isSynced() → @Published sessionSynced
  ├─ cleanup: clear resyncingRunnersInternal, syncingUuids, syncInProgress
  ├─ failed sensors: recordDisconnection (must reconnect)
  ├─ succeeded sensors: refreshStorage (re-fetch flash info)
  └─ notify()                             // UI clears spinner, shows checkmark

Sensors now report device.isSynced() == true. Button changes to “Start”.

Start Recording (~1–3 seconds)

User taps “Start” →

1. Validate (stateQueue)

beginSession(runnerId)
  ├─ guard: phase .idle, no pending connections
  ├─ collect dots where connectionPhase == .ready
  ├─ guard: if 2+ dots, ALL must have device.isSynced() == true
  ├─ guard: none already recording
  └─ configure each dot (output rate, filter)

2. Start each sensor sequentially (sdkQueue)

setPhase(.startingRecording)              // UI: "Starting..."

for each dot (one at a time):
  device.startRecording(0xFFFF)           // SDK command: record indefinitely
  waitForRecordingState(target: true)     // poll every 0.3s, 10s timeout
    └─ when recordingStatus == .isRecording:
        syncRecordingState()              // @Published isRecording = true
        done(true)                        // next dot

3. All done (stateQueue)

if all succeeded:
  setPhase(.recording)                    // UI: red "Stop" button
  ExportManager.clearCart()               // clear stale export state
if any failed:
  setPhase(.error("Recording failed...")) // UI: error banner

Stop Recording (~1–2 seconds)

User taps “Stop” →

1. Validate and stop each sensor (stateQueue → sdkQueue)

endSession(runnerId)
  ├─ guard: phase == .recording
  ├─ collect connected dots with connectionPhase == .ready
  ├─ setPhase(.stoppingRecording)              // UI: "Stopping..."
  │
  for each dot:
    ├─ check live SDK property: device.recording.recordingStatus
    ├─ if already idle: skip, call syncRecordingState()
    └─ if recording: device.stopRecording()
        waitForRecordingState(target: false)   // poll until stopped
          └─ syncRecordingState()               // @Published isRecording = false

2. Finalize (stateQueue)

if all succeeded:
  setPhase(.idle)                         // UI: back to "Start"
  2-second settle delay                   // sensor finalizes flash
  then: getFlashInfo() on each dot        // refresh storage bars
if any failed:
  setPhase(.error("Failed to stop..."))   // UI: error banner

Sensors stay synced after stop — endSession does not call stopSync. The user can record again without re-syncing.

Two-Step Process (Reference)

Sync and recording are separate actions. When a runner has 2+ sensors, the user must sync first, then start recording. beginSession guards on device.isSynced() and blocks recording if any sensor is not synced. With only 1 sensor, recording starts directly (no sync needed).

StepEntry PointPreconditionPhase Transition
Sync resyncRunner(runnerId:) or syncSession() 2+ ready sensors, no other sync active Runner stays .idle; tracked via resyncingRunners
Record beginSession(runnerId:) or beginSession() All sensors isSynced() if 2+, none already recording idle → startingRecording → recording

The solo runner convenience methods (syncSession(), beginSession()) create or update an ephemeral runner with ID "__single__" from all connected ready sensors, then delegate to the multi-runner methods.

Step 1: Sync — resyncRunner(runnerId:)

Called when the user taps "Sync Sensors" on a runner card (or the Resync button). Runs on stateQueue:

resyncRunner(runnerId:)
    └─ stateQueue.async
        ├─ Guard: runnerPhasesInternal[runnerId] == .idle
        ├─ Guard: !resyncingRunnersInternal.contains(runnerId)
        ├─ Guard: no runner syncing (no .isSyncActive phases, resyncingRunnersInternal empty)
        ├─ Guard: runner exists in RunnerStore with sensor UUIDs
        ├─ Collect dots in .ready phase for this runner's UUIDs
        ├─ Guard: dots.count ≥ 2
        │
        ├─ resyncingRunnersInternal.insert(runnerId)
        ├─ registry.syncingUuids.formUnion(uuids)
        ├─ registry.syncInProgress = true
        ├─ @Published resyncingRunners.insert(runnerId) on main
        │
        └─ performSync(dots:, runnerId:) { result in
               // Cleanup FIRST — before any refreshStorage calls
               resyncingRunnersInternal.remove(runnerId)
               registry.syncingUuids.subtract(runner.sensorUuids)
               registry.syncInProgress = (any .isSyncActive || resyncingRunnersInternal non-empty)
               @Published resyncingRunners.remove(runnerId) on main

               // Reset failed sensors so scan → connect can recover them
               for uuid in result.failedUuids:
                   registry.recordDisconnection(uuid)

               // Refresh storage only for sensors that succeeded
               refreshStorage(dots: succeededDots)
           }

Note: resyncRunner does NOT call setPhase(.syncing, ...). The resync state is tracked separately via resyncingRunnersInternal / @Published resyncingRunners. The runner phase stays .idle throughout the resync — the UI shows resync progress via the resyncingRunners set, not the session phase. registry.syncInProgress is set directly to block connections during resync.

Step 2: Record — beginSession(runnerId:)

Called when the user taps "Start" on a runner card. Runs on stateQueue:

beginSession(runnerId:)
    └─ stateQueue.async
        ├─ Guard: runnerPhasesInternal[runnerId] is .idle or .error
        ├─ Guard: connectQueue is empty AND connectInProgress is nil
        ├─ Guard: runner exists in RunnerStore with sensor UUIDs
        ├─ Collect dots in .ready phase for this runner's UUIDs
        ├─ Guard: none of the dots are currently recording
        ├─ Guard: dots.count ≥ 2 implies all dots report device.isSynced()
        │
        ├─ Configure each dot: dot.configure(outputRate:, filterIndex:)
        ├─ setPhase(.startingRecording, forRunner: runnerId)
        │
        └─ performStartRecording(dots:, runnerId:)
               ├─ DotOperationRunner.runAll: dot.startRecording(seconds: 0xFFFF)
               ├─ On success: setPhase(.recording, forRunner: runnerId)
               └─ On failure: setPhase(.error(...), forRunner: runnerId)

Key difference from old design: beginSession no longer calls performSync. It validates that sensors are already synced (via device.isSynced()) and proceeds directly to recording. If sensors aren't synced, the UI shows "Sync Sensors" instead of "Start" and routes to resyncRunner.

performSync(dots:runnerId:completion:)

Returns a SyncResult with per-sensor success info:

struct SyncResult {
    let allSuccess: Bool
    let succeededUuids: Set<String>
    let failedUuids: Set<String>
    let errorMsg: String?
}
performSync(dots:, runnerId:, completion:)
    └─ Snapshot: devices = dots.map { $0.device }
    │     (must capture BEFORE dispatching to sdkQueue, because
    │      the SDK will disconnect/reconnect and device refs change)
    │
    └─ sdkQueue.async {
           // Stop any previously synced devices first
           for device in devices where device.isSynced():
               DotSyncManager.stopSync([device])

           DotSyncManager.startSync(devices) { results in
               stateQueue.async {
                   // Parse results: each has address, success, status
                   // Match each result back to dot UUID
                   // Dots not in results at all count as failed
                   dots.forEach { $0.refreshSyncStatus() }

                   // NOTE: refreshStorage and syncingUuids cleanup are NOT
                   // done here — the caller is responsible for cleanup
                   // AFTER clearing sync flags, so refreshStorage doesn't
                   // get blocked by isBusyInternal.
                   completion(SyncResult(...))
               }
           }
       }

Per-UUID Suppression via syncingUuids

During sync, the SDK internally disconnects and reconnects each sensor. This fires onDeviceDisconnected and onDeviceConnectSucceeded delegate callbacks. Without suppression, DotManager would:

  • Mark the sensor as disconnected (clear phase, update UI)
  • Try to re-initialize it (flash queries, bind device)
  • Corrupt the sync by interfering with the SDK's internal reconnection

The fix is syncingUuids: Set<String> on DotRegistry:

// In onDeviceDisconnected:
if registry.syncingUuids.contains(uuid) {
    return  // Suppress — SDK is managing this device
}

// In onDeviceConnectSucceeded:
if registry.syncInProgress && registry.syncingUuids.contains(uuid) {
    registry.recordReconnection(device)  // lightweight, no phase change
    return  // Don't initialize — SDK is managing this device
}

Why per-UUID, not a global flag? If Runner A (sensors 1, 2, 3) is syncing and Runner B (sensors 4, 5, 6) has a sensor disconnect, a global syncInProgress flag would suppress Runner B's disconnect handling too. Per-UUID suppression only affects the sensors actually involved in the sync.

Device Reference Freezing

syncingUuids also prevents device reference updates during sync. Both recordDiscovery() and recordReconnection() check:

func recordDiscovery(_ device: DotDevice) {
    let uuid = device.uuid
    if syncingUuids.contains(uuid) { return }  // Don't update device ref
    byUuid[uuid]?.device = device
    // ...
}

This is critical because performSync captures device references before dispatching to sdkQueue. If a discovery event updated the registry's device reference mid-sync, the captured references would be stale but the registry's would be new — causing the sync completion handler to operate on mismatched state.

setPhase and Sync Flag Maintenance

private func setPhase(_ phase: SessionPhase, forRunner runnerId: String) {
    // Must be on stateQueue
    runnerPhasesInternal[runnerId] = phase

    // Keep syncInProgress in lockstep — accounts for both session sync
    // phases AND active resync operations
    registry.syncInProgress = runnerPhasesInternal.values.contains { $0.isSyncActive }
        || !resyncingRunnersInternal.isEmpty

    // If this runner is no longer syncing, release its UUIDs
    if !phase.isSyncActive {
        let sensorUuids = Set(RunnerStore.shared.runner(forId: runnerId)?.sensorUuids ?? [])
        registry.syncingUuids.subtract(sensorUuids)
    }

    // Clear stale export cart when a new recording begins
    if phase == .recording {
        DispatchQueue.main.async {
            ExportManager.shared.clearCart()
            ExportManager.shared.resetExport()
        }
    }

    // Safety net: when returning to idle, purge connection-tracking entries
    // for devices that are already connected. Prevents stale hasPendingConnections
    // from blocking the UI after edge-case races.
    if phase == .idle {
        registry.connectQueue.removeAll { uuid in
            registry.byUuid[uuid]?.connectionPhase.isConnected == true
        }
        if let ip = registry.connectInProgress,
           registry.byUuid[ip]?.connectionPhase.isConnected == true {
            registry.connectInProgress = nil
        }
    }

    // Snapshot to main thread
    let snapshot = runnerPhasesInternal
    DispatchQueue.main.async { self.runnerPhases = snapshot }
    notify()  // also snapshots resyncingRunnersInternal → resyncingRunners
}

Note: notify() now includes a snapshot of resyncingRunnersInternal alongside the other state. This consolidates all @Published updates through a single mechanism — no more scattered DispatchQueue.main.async calls for resyncingRunners.

endSession(runnerId:) — Stop Recording

Called when the user taps “Stop”. Runs on stateQueue, sends stop commands via DotOperationRunner.runAll. Does not call stopSync — sensors stay in measurement mode (synced) after recording stops, allowing multiple recordings without re-syncing.

Dot filtering

  • Filters runner’s sensor UUIDs by isConnected AND connectionPhase == .ready
  • Dots still in .initializing are skipped — sending stop during flash queries can interfere
  • The UI also disables the stop button while any runner dot is still initializing (same sensorsInitializing / allDotsReady guard used for the start button)

Per-sensor stop logic

  • Before calling dot.stopRecording(), reads the live SDK property device.recording.recordingStatus
  • If not .isRecording (sensor already idle after power cycle or disconnect), skips stop and calls done(true). Also calls dot.syncRecordingState() on main thread to sync the @Published flag with the live SDK state.
  • If .isRecording, calls dot.stopRecording() which sends the SDK command and enters waitForRecordingState

waitForRecordingState

Polls device.recording.recordingStatus (the live SDK property) on sdkQueue every 0.3s. On success, calls syncRecordingState() and then the completion handler in the same DispatchQueue.main.async block. syncRecordingState() uses setOnMain which runs synchronously when already on main thread, so the flag is guaranteed to update before the completion triggers the runner phase transition.

UI Flow: RunnerCard Action Button

The RunnerCard's primary action button dynamically changes based on runner state:

StateButton LabelColorAction
No sensors assigned No Sensors Gray (disabled) —
2+ sensors, not synced Sync Sensors Orange resyncRunner
Sensors synced (or 1 sensor) Start [Runner] Green beginSession
Recording Stop [Runner] Red endSession
Syncing / Starting / Stopping Syncing... / Starting... / Stopping... Gray (disabled) —

The resync button and trash icon in the RunnerCard header are grayed out and disabled while syncing is in progress.
