Unit Tests

Test target structure, coverage, and testability patterns.

Running Tests

Tests live in the Brooks-Movella-AppTests target. Run from Xcode via Product → Test (⌘U), or from the command line:

xcodebuild test \
  -scheme "Brooks-Movella-App" \
  -destination 'platform=iOS Simulator,name=iPhone 15'

No SDK or Bluetooth is needed — all tests exercise pure logic extracted from the managers.

Manual Test: Export Retry Folder Matching

Verifies that retried export files land in the same session folder instead of creating a duplicate with a _1 suffix.

  1. Connect 2+ sensors and record a session.
  2. Go to Export, fetch recordings, and start an export of 3+ files from one session.
  3. During the BLE transfer, force-fail one file (e.g., move a sensor out of BLE range or power it off).
  4. Wait for the export to complete with at least 1 failed file.
  5. Open the Files app and navigate to Brooks-Movella-App/Exports/. Verify the session folder (e.g., 2026-03-28_14-30-00/) contains the successful CSVs and a metadata.csv with a Session ID row.
  6. Back in the app, tap Retry Failed.
  7. After the retry completes, check the Files app again. The retried file should appear in the same session folder — no _1 duplicate folder should exist.
  8. Open metadata.csv and verify it now includes the retried file’s recording timestamp alongside the originals.

Testability Patterns

Dependency injection for isolation

Both RunnerStore and SensorNameStore are singletons with static let shared. To test without polluting the shared instance:

  • RunnerStore accepts an optional fileURL in its initializer. Tests pass a temp file path; production uses the default Documents/runners.json.
  • SensorNameStore accepts a UserDefaults instance and key. Tests pass UserDefaults(suiteName:) for isolation; production uses .standard.

Extracted pure decision functions (DotManagerLogic & ExportManagerLogic)

Both DotManager and ExportManager are singletons that require the Movella SDK — they can't be instantiated in tests. The solution: extract every decision (guard checks, path routing, result parsing, task triage) into pure static functions on DotManagerLogic and ExportManagerLogic enums. These take value-type inputs and return value-type outputs — no SDK, no queues, no singletons.

  • DotSnapshot — lightweight struct (isReady, isSynced, isRecording) replacing Dot in precondition checks
  • ConnectPath — enum of the 4 initialization paths, determined by flag inputs
  • DotIdentifier — struct with address + macAddress for sync result matching
  • PhaseTransitionEffects — struct describing what setPhase should do (sync flags, export cart, stale connections)
  • ExportTaskSnapshot — lightweight struct (hasPacketLoss, fileExists) for retry triage decisions
  • TriageAction — enum (.markSuccess, .addToPipeline, .deleteAndRecheck) returned by task triage

The pattern: test decisions, not side effects. The Bluetooth calls are side effects that happen after the decision. The decisions are pure functions that can be tested with simple inputs.

Extracted static functions

DotManager.aggregateSessionPhase(from:) was extracted from a computed property into a static function. This lets tests call it with arbitrary [String: SessionPhase] dictionaries without needing to instantiate DotManager.

Pure enums

SessionPhase and ConnectionPhase are nonisolated enums with no SDK dependencies. Their computed properties (isTransitioning, isError, isSyncActive, isFailed, isConnected) can be tested directly with zero setup.
